## Resumen

Primera versión estable del producto develOP.
Chatbot multi-tenant end-to-end: widget embebible, onboarding completo sin SQL, panel admin y dashboard cliente.

---

## Qué incluye

### Widget & Runtime
- Widget embebible vanilla JS (~5KB), sin dependencias React en el sitio del cliente
- Conversación con Vertex AI Gemini 2.5 Flash (streaming)
- Captura de leads automática con tool calling
- Handoff a WhatsApp con contexto de la conversación
- Domain whitelist — CORS dinámico por bot vía `BotConfig.allowedDomains`
- Rate limiting in-memory (60 req/min por IP)

### Panel Admin (`/admin`)
- Wizard onboarding 5 pasos: crea Org + User + Bot + envía credenciales en un solo flujo
- Gestión global de chatbots (`/admin/chatbots`) con bulk operations
- Página unificada de bot con 5 tabs: Overview, Config, KB, Activity, Install
- Editor de configuración con preview en vivo y diff modal antes de guardar
- Re-envío manual de credenciales desde página del cliente
- Sistema de alertas con 7 tipos + notificación email/Telegram en alertas críticas
- Audit log completo de todas las acciones
- Cron: detector de issues + reportes semanales automáticos (lunes 9am ARG)
- Tab "Instalar" con snippets por plataforma: HTML, WordPress, Tiendanube, Shopify, Wix, Squarespace

### Dashboard Cliente (`/dashboard`)
- Login con credenciales temporales + cambio forzado de password al primer login
- Métricas en formato negocio (conversaciones, leads, tokens)
- Leads en tiempo real con polling 30s
- Notificación email al capturar lead
- Personalización del bot: color, posición, avatar, welcome message
- Vista de instalación con snippet copy-paste en `/dashboard/chatbot/install`
- Reporte semanal automático por email

## Fixes críticos aplicados en R25 (pre-tag)

| Archivo | Bug | Fix |
|---|---|---|
| `src/auth.ts` | `passwordResetRequired` nunca entraba al JWT en primer login | `trigger === 'signIn'` incluido + propagación explícita |
| `src/app/cambiar-password/actions.ts` | JWT cookie no se actualizaba → middleware redirigía de vuelta | `unstable_update()` fuerza refresh del JWT antes del navigate |
| `src/lib/security/validate-origin.ts` | `develop.com.ar` bypass después del check de `allowedDomains` | Bypass movido antes del check |
| `src/app/(protected)/admin/clients/[clientId]/page.tsx` | `params.orgSlug` siempre `undefined` (route es `[clientId]`) | Tipo corregido a `clientId` |
| `src/app/api/chatbot/[slug]/health/route.ts` | Health endpoint bloqueaba monitoring (no envía `Origin`) | `validateOrigin` removido del health route |
